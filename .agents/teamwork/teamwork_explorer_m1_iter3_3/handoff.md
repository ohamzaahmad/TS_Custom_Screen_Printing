## Executive Summary

Lines 152–183 in `index.css` define base styling for interactive elements (`button`, `.btn`, `.btn-gradient`, `[role="button"]`, `nav a`, `nav button`, `.nav-link`, `.badge`, `.tag-badge`, `[class*="badge"]`, and `input, textarea, select`). 

Our empirical investigation reveals that because these rules are declared **unlayered** (outside any `@layer`), they trigger a critical **CSS Cascade Level 5 precedence conflict** against Tailwind CSS v4:
1. **Unlayered author styles take cascade precedence over all layered author styles** (including Tailwind v4's `@layer utilities`, `@layer components`, and `@layer base`).
2. Every button, nav item, and badge on the website has its Tailwind tracking utilities completely crushed:
   - Desktop Navigation buttons (`Navbar.tsx:148`): `tracking-[0.24em]` (2.4px at 10px) is crushed to `0.5px` (0.05em)—a **79% spacing reduction**.
   - Desktop "Start Order" CTA (`Navbar.tsx:165`): `tracking-[0.2em]` (2.2px at 11px) is crushed to `0.55px` (0.05em)—a **75% spacing reduction**.
   - Hero "Start A Project" CTA (`Home.tsx:270`): `tracking-widest` (1.4px at 14px) is crushed to `0.7px` (0.05em)—a **50% spacing reduction**.
   - Guide buttons (`Home.tsx:368`): `tracking-[0.18em]` (1.98px at 11px) is crushed to `0.55px` (0.05em)—a **72% spacing reduction**.
3. Utility classes such as `normal-case`, `font-sans`, `font-normal`, `font-mono`, and `tracking-normal` fail completely on buttons and inputs.
4. In `Footer.tsx:96-128`, the FAQ accordion `<button>` causes child `<p>` elements (the answer body) to inherit uppercase Oswald, rendering long explanatory answers in all caps.

Wrapping lines 106–183 (headings, buttons, nav links, badges, and form inputs) inside a unified `@layer base { ... }` block completely resolves the cascade conflict:
- Default buttons, nav links, and badges retain Oswald uppercase 0.05em letter spacing when unstyled.
- Any Tailwind utility class (`tracking-[0.24em]`, `tracking-normal`, `font-sans`, `normal-case`, `font-mono`, `text-slate-400`, `bg-orange-500`) cleanly overrides base styles without specificity friction.

## 2. Logic Chain

1. **W3C CSS Cascading and Inheritance Level 5 Specification**:
   The cascade sorting precedence for normal (non-important) author rules is:
   `User Agent` → `User` → `@layer base` → `@layer components` → `@layer utilities` → **Unlayered Author Styles**.
   Unlayered normal styles ALWAYS take precedence over ANY layered style, regardless of selector specificity or declaration order.
2. **Tailwind CSS v4 Architecture**:
   Tailwind v4 compiles `@import "tailwindcss";` into internal CSS layers (`@layer base, components, utilities`). All utility classes (e.g., `tracking-[0.24em]`, `font-sans`, `normal-case`, `text-white`, `text-orange-500`) are placed in `@layer utilities`.
3. **The Root Mechanism of the Defect**:
   Because `button`, `nav a`, `nav button`, and `[class*="badge"]` in `index.css:152-175` are declared without `@layer`, they are unlayered. Therefore:
   - An unlayered `button { letter-spacing: 0.05em; }` outranks `.tracking-[0.24em]` from `@layer utilities`.
   - An unlayered `button { text-transform: uppercase; }` outranks `.normal-case` from `@layer utilities`.
   - An unlayered `button { font-family: Oswald; }` outranks `.font-sans` from `@layer utilities`.
   - An unlayered `input { font-family: Poppins; }` outranks `.font-mono` from `@layer utilities`.
4. **Resolution via `@layer base`**:
   Moving these selectors inside `@layer base { ... }` changes their cascade status from Unlayered to Layer 1 (`base`).
   Because `@layer utilities` has higher cascade precedence than `@layer base`:
   - When an element has NO utility classes, `@layer base` defaults apply: buttons get Oswald, uppercase, and 0.05em letter spacing; form inputs get Poppins with normal letter spacing.
   - When an element DOES have utility classes (`tracking-[0.24em]`, `font-sans`, `normal-case`, `font-mono`), `@layer utilities` wins cleanly.
5. **Comparison: `@layer base` vs `@layer components`**:
   - Both `@layer base` and `@layer components` are lower in precedence than `@layer utilities`, so either layer allows utility classes to override them.
   - However, `button`, `nav a`, `nav button`, and `input, textarea, select` are HTML tag selectors representing fundamental document elements. In CSS architecture, element defaults belong strictly in `@layer base`.
   - Grouping the companion class aliases (`.btn`, `[role="button"]`, `.badge`, `.nav-link`) into `@layer base` alongside `button` guarantees that all baseline interactive primitives share the exact same layer precedence, and can be overridden by any component class in `@layer components` or utility class in `@layer utilities`.
   - Splitting them across `@layer base` and `@layer components` introduces unnecessary layer fragmentation without any functional benefit.
